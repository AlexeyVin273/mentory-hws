# 12. Review состояния небольшого dashboard

Самостоятельно запускаемая версия на JavaScript и React. Основа — урок 08;
избранное вынесено в useFavorites по примеру урока 11. Стили и вымышленные
данные сохранены из урока 08. Сервер и дополнительные функции не нужны.

## Запуск

Из этого каталога (Node.js 24):

```sh
npm install
npm run dev
```

Открой адрес, который напечатает Vite, с путём `/mentory-hws/`.
Проверки: `npm run lint` и `npm run build`.

## Владельцы состояния

```text
App — без state
└── CourseCatalog
    ├── search
    ├── category
    ├── selectedCourseId
    ├── favoriteIds (state внутри единственного вызова useFavorites)
    ├── ControlledSearch ← search, onSearchChange
    ├── CourseListView ← filteredCourses, selectedCourseId, favoriteIds, обработчики
    │   └── CourseCard ← course, isSelected, isFavorite, обработчики
    ├── выбранная CourseCard ← selectedCourse, isFavorite, onToggleFavorite
    └── Panel избранного ← названия favoriteCourses и их количество
```

CourseCatalog — ближайший общий владелец данных для поиска, списка,
выбранной карточки и избранного. Хук организует логику избранного, но его
состояние принадлежит экземпляру CourseCatalog. Дочерние компоненты
получают значения и сообщают о действиях через обработчики.

В state хранятся только пользовательские значения и идентификаторы.
courses — неизменяемый импорт из JSON. filteredCourses, selectedCourse,
favoriteCourses и счётчики вычисляются при рендере.
Выбранный курс ищется в полном courses и отображается вне результатов
фильтрации, поэтому остаётся видимым даже при пустой выдаче.

## Два отклонённых варианта

1. Хранить избранное в каждой CourseCard. Тогда общий счётчик и очистка
   требуют дополнительной координации, две карточки одного курса могут
   расходиться, а размонтирование при фильтрации уничтожает локальный state.
2. Хранить filteredCourses и selectedCourse в state вместе с исходными
   значениями. Это дублирует данные и требует синхронизации: список может
   отстать от поиска, а объект выбранного курса — от исходного каталога.

## Ручная проверка

1. Выбери React-интерфейсы и добавь их в избранное. Выбор и избранное —
   независимые действия.
2. Выбери категорию Quality и введи `несуществующий курс`. Выдача пуста,
   выбранная карточка React остаётся видимой, избранное содержит один курс.
3. Очисти избранное. Поиск, категория и выбранная карточка сохраняются;
   счётчик избранного равен нулю, кнопка карточки предлагает добавить курс.
4. Очисти поиск. Категория Quality и выбранная карточка React сохраняются;
   в выдаче появляется курс «Проверка поведения UI».
5. Верни все категории и добавь React в избранное через выбранную карточку.
   Кнопка той же карточки в списке тоже должна обновиться.

Предыдущие уроки остаются отдельными запускаемыми версиями.
